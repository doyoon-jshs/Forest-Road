# 지형 기반 임도 노선 최적화

DEM(수치표고모델)을 기반으로 임도(산림 도로) 노선을 자동으로 설계하고 최적화하는 제주과학고등학교 정보 동아리 COMMON의 동아리 발표회 연구 프로젝트입니다.

## 구조

- `backend/` — FastAPI. DEM 업로드/병합, 지형 시각화, 노선 최적화, 절/성토 물량 산출 API
- `frontend/` — React + Leaflet. DEM 업로드 UI, 지도 위 시각화, 클릭 기반 노선 탐색 + 종단면도

## 지형 시각화

DEM(GeoTIFF)을 업로드하면 음영기복·경사도·고도 히트맵을 지도 위에 오버레이로 볼 수 있습니다(투명도 조절 가능). 고도 히트맵은 DEM의 실제 최저~최고 고도에 맞춰 색상(초록→노랑→갈색→흰색)을 자동으로 매핑하고, 바다는 투명 처리합니다. 등고선(벡터)도 자동 간격으로 오버레이할 수 있고, 지도에 마우스를 올리면 실시간으로 고도가 표시됩니다.

여러 도엽(타일)을 한 번에 선택하면 서버에서 자동으로 병합(mosaic)해 하나의 DEM으로 처리하며, 서로 다른 좌표계의 원본 DEM은 UTM 52N(EPSG:32652)으로 자동 재투영합니다.

오버레이 이미지는 UTM(등거리 미터 격자)에서 계산한 뒤 화면 표시 직전에 위경도(EPSG:4326) 격자로 재투영합니다. 위도에 따라 경도 1도의 실거리가 달라지기 때문에(제주 위도 약 33.5도에서는 위도 1도의 약 83%) UTM 격자를 그대로 내보내면 실제 지도와 어긋나는데, 이 재투영 과정에서 그 왜곡을 보정합니다.

## 노선 최적화

지도에서 시작점 → (경유지 여러 개 추가 가능) → 도착점을 순서대로 클릭하면, `skimage.graph.MCP_Geometric` 기반 최소비용경로 탐색으로 노선을 계산합니다 ([routing.py](backend/app/routing.py)). 경유지가 있으면 구간별로 나눠 탐색한 뒤 하나의 노선으로 이어붙이며, 비용표면(경사·유역면적 등)은 DEM 전체에 대해 한 번만 계산해 모든 구간이 재사용합니다.

**비용함수**
- 기본 비용 = 1 + 경사 페널티(설계기준 14% 초과 시 급증, 절대상한 30% 초과는 통행 불가) + 계곡 횡단 페널티
- 계곡 횡단 페널티는 DEM에서 D8 흐름누적(flow accumulation)으로 유역면적을 추정해서 계산합니다. 유역면적이 클수록(=하천이 클수록) 횡단 비용이 커지고, 상대적 규모(현재 DEM 내 백분위수)로 암거/교량을 구분합니다. 실제 설계에서는 합리식(Q=CIA) 등 정밀 수리계산으로 대체가 필요한 근사치입니다. 유역면적만으로 판단하면 완만한 지형에서 D8 알고리즘이 만드는 아티팩트(실제로는 오목하지 않은데 유량이 쏠리는 셀)까지 계곡으로 오판할 수 있어서, 해당 셀이 상하좌우 이웃보다 실제로 낮은(오목한) 지형인지도 같이 확인해 걸러냅니다.
- 바다는 nodata가 아니라 실제 고도값(대체로 0 부근)을 가진 DEM(Copernicus 등)에서도 통행 불가로 정확히 처리됩니다.
- 성능을 위해 DEM을 최대 2000px 격자로 다운샘플링한 뒤 탐색합니다(제주 전체 기준 셀 약 57m, 2초 이내). `MAX_ROUTING_DIM` 상수로 조정 가능하며, 값이 클수록 노선이 덜 각지지만 탐색 시간이 늘어납니다.

**곡선반경 스무딩**: 격자 탐색 결과는 8방향 이동 때문에 각지게 나오므로, 경로를 그대로 쓰지 않고 후처리합니다. Douglas-Peucker로 거의 일직선인 중간점을 제거해 실제 방향전환 지점만 남기고, Chaikin 코너커팅을 여러 번 적용해 각진 부분을 둥글립니다. 스무딩된 좌표마다 3점 외접원으로 곡선반경을 계산해 설계기준(최소곡선반경 15m 근사) 미달 구간을 보고합니다.

결과로 노선 좌표열, 종단면도(거리·고도·구간별 경사), 전체 길이, 최대경사, 계곡 횡단 목록(구조물 종류), 최소곡선반경과 기준 미달 구간을 반환합니다. 교량 구간은 지도 위 노선에도 굵은 보라색 선으로 겹쳐서 표시됩니다.

**대안 노선 생성**: 같은 시작/경유/도착점이라도 알고리즘은 결정론적이라 항상 같은 노선이 나옵니다. "다른 경로 생성" 버튼을 누르면 요청에 랜덤 시드를 실어 보내고, 서버는 하드 제약(통행 불가)은 그대로 둔 채 비용표면 나머지 값에 그 시드로 생성한 ±15% 노이즈를 곱해 재탐색합니다 — 비슷한 비용의 대안 경로 중 하나가 선택되며, 같은 시드는 항상 같은 결과를 재현합니다.

## 절/성토 물량 산출

노선의 각 station을 잇는 직선 구배를 설계 노면으로 보고, 원본 해상도 DEM에서 10m 간격으로 재샘플링한 실제 지형고와 비교해 절/성토 단면적과 물량을 계산합니다 ([earthwork.py](backend/app/earthwork.py)).

- 단면적 = 도로폭(기본 4m, 조절 가능) × 절/성토 깊이 + 사면기울기 계수 × 깊이² (절토 1:1, 성토 1:1.5 가정) — 표준 사다리꼴 단면 공식
- 물량은 양단면적평균법(end-area method)으로 구간 누적
- 종단면도에 지형선과 설계선을 같이 그리고, 그 사이를 절토/성토 음영으로 표시
- 노선 최적화 단계에서 "교량"으로 분류된 구간은 성토 계산에서 제외하고 대신 교량 길이로 따로 집계합니다 — 안 그러면 깊은 계곡을 흙으로 다 메우는 것처럼 계산되어 비현실적인 성토량이 나옵니다.

## 다중 노선 비교 및 내보내기

계산된 노선을 "비교용으로 저장"하면 지도 위에 색이 다른 점선으로 계속 남아있고, 새 노선을 이어서 계획할 수 있습니다. 저장한 노선들은 지도 우상단 비교 패널에서 길이·최대경사·절토·성토·교량 길이를 한눈에 비교하고, 노선별로 보이기/숨기기를 토글할 수 있습니다.

각 노선은 GeoJSON(좌표열 + 지표 속성) 또는 CSV(종단면도 상세 데이터)로 내보낼 수 있고, 저장된 노선 전체를 하나의 GeoJSON으로 한 번에 내보낼 수도 있습니다.

## 알려진 한계

- 도로 중심선 기준 종단 방향만 고려하고 횡단(도로 폭 방향) 지형 경사는 반영하지 않습니다 — 실제보다 단순화된 근사치입니다.
- 완전히 평탄/대칭인 지형에서는 D8 흐름누적 알고리즘이 아티팩트(특정 지점에 유량이 과도하게 몰리는 현상)를 만들 수 있습니다 — 노이즈가 있는 실제 지형에서는 거의 발생하지 않습니다.
- 계곡 횡단 구조물 비용, 절/성토 물량 모두 근사치이며, 실제 설계에는 정밀 수리계산과 현장 측량이 필요합니다.
- 보전구역·문화재구역 등 법적 제약 조건은 아직 반영되지 않았습니다.

## 실행 방법

### 백엔드

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

### 프런트엔드

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 http://localhost:5173 접속 후 GeoTIFF DEM 파일을 업로드하면 됩니다.

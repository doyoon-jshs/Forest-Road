# 임도 노선 설계 소프트웨어

DEM(수치표고모델) 기반 임도(산림 도로) 노선 설계·최적화 개인 연구 프로젝트.

## 구조

- `backend/` — FastAPI. DEM 업로드/병합, 경사도·음영기복 계산, 노선 최적화 API
- `frontend/` — React + Leaflet. DEM 업로드 UI, 지도 위 음영기복/경사도 시각화, 클릭 기반 노선 탐색 + 종단면도

## 1단계: 지형 뷰어 (완료)

DEM(GeoTIFF) 업로드 → 경사도·음영기복·고도 히트맵 계산 → 지도에 오버레이(투명도 조절 가능). 고도 히트맵은 DEM의 실제 최저~최고 고도에 맞춰 색상(초록→노랑→갈색→흰색)을 자동 매핑, 바다는 투명 처리. 여러 도엽(타일)을 한 번에 선택하면 서버에서 자동 병합(mosaic) 후 하나의 DEM으로 처리. 서로 다른 좌표계의 원본 DEM은 UTM 52N(EPSG:32652)으로 자동 재투영. 등고선(벡터, `skimage.measure.find_contours` 기반, 간격 자동 산정) 오버레이와 지도 마우스오버 고도 조회 지원.

오버레이 이미지는 UTM(등거리 미터 격자)에서 계산한 뒤 화면 표시 직전에 위경도(EPSG:4326) 격자로 재투영한다 — Leaflet의 `imageOverlay`는 이미지를 위경도 사각형에 선형으로 늘려 붙이는데, 위도에 따라 경도 1도의 실거리가 달라지므로(제주 위도 약 33.5도에서는 위도 1도의 약 83%) UTM 격자를 그대로 내보내면 동서 방향으로 왜곡되어 실제 지도와 어긋났던 버그를 수정.

## 3단계: 노선 최적화 엔진 (현재, 2단계는 통합되어 생략)

지도에서 시작점 → (경유지 여러 개 추가 가능) → 도착점을 순서대로 클릭하면 `skimage.graph.MCP_Geometric` 기반 최소비용경로 탐색으로 노선을 계산 ([routing.py](backend/app/routing.py)). 경유지가 있으면 구간별로 나눠 탐색한 뒤 하나의 노선(좌표열·종단면도)으로 이어붙임 — 비용표면(경사·유역면적 등)은 DEM 전체에 대해 한 번만 계산해 모든 구간이 재사용:

- 비용표면 = 1 + 경사 페널티(설계기준 14% 초과 시 급증, 절대상한 30% 초과는 통행 불가) + 계곡 횡단 페널티
- 계곡 횡단 페널티: DEM에서 D8 흐름누적(flow accumulation)으로 유역면적을 추정하고, 그 지점의 유역면적이 클수록(=하천이 클수록) 횡단 비용이 커짐. 상대적 규모(현재 DEM 내 백분위수)로 암거/교량을 구분 — 실제 설계에서는 합리식(Q=CIA) 등 정밀 수리계산으로 대체 필요
- 바다는 nodata가 아니라 실제 고도값(대체로 0 부근)을 가진 DEM(Copernicus 등)에서도 통행 불가로 정확히 처리됨 (고도 0 이하는 바다로 간주)
- 성능을 위해 DEM을 최대 2000px 격자로 다운샘플링한 뒤 탐색 (제주 전체 기준 셀 약 57m, 2초 이내). `MAX_ROUTING_DIM` 상수로 조정 가능 — 값이 클수록 노선이 덜 각지지만 탐색 시간이 늘어남
- 결과: 노선 좌표열, 종단면도(거리·고도·구간별 경사), 전체 길이, 최대경사, 계곡 횡단 목록(구조물 종류), 최소곡선반경·기준 미달 구간

**곡선반경 스무딩**: 격자 탐색 결과는 8방향 이동 때문에 각지게 나오므로, 경로를 그대로 쓰지 않고 후처리한다 — ① Douglas-Peucker로 거의 일직선인 중간점을 제거해 실제 방향전환 지점만 남기고 ② Chaikin 코너커팅을 여러 번 적용해 각진 부분을 둥글린다. 스무딩된 좌표마다 3점 외접원으로 곡선반경을 계산해 설계기준(최소곡선반경 15m 근사) 미달 구간을 `tight_curves`로 보고한다. 비용표면 재검증 없이 순수 후처리라 빠르지만, 스무딩된 곡선이 원래 최적경로에서 살짝 벗어날 수 있음.

알려진 한계: 완전히 평탄/대칭인 지형에서는 D8 흐름누적 알고리즘이 아티팩트(특정 지점에 유량이 과도하게 몰리는 현상)를 만들 수 있음 — 노이즈가 있는 실제 지형에서는 거의 발생하지 않음.

## 4단계: 절/성토 물량 산출 (완료)

노선의 각 station(=path/profile 지점)을 잇는 직선 구배를 설계 노면으로 보고, 원본 해상도 DEM에서 10m 간격으로 재샘플링한 실제 지형고와 비교해 절/성토 단면적·물량을 계산 ([earthwork.py](backend/app/earthwork.py)):

- 단면적 = 도로폭(4m 가정) × 절/성토 깊이 + 사면기울기 계수 × 깊이² (절토 1:1, 성토 1:1.5 가정) — 표준 사다리꼴 단면 공식
- 물량은 양단면적평균법(end-area method)으로 구간 누적
- 종단면도에 지형선(회색)과 설계선(파랑)을 같이 그리고, 그 사이를 절토(빨강)/성토(파랑) 음영으로 표시

한계: 도로 중심선 기준 종단 방향만 고려하고 횡단(도로 폭 방향) 지형 경사는 반영하지 않음 — 실제보다 단순화된 근사치. 도로폭·사면기울기는 고정값이라 추후 임도 등급별로 조정 가능하게 만들 수 있음.

아직 없는 것: 보전구역 등 하드 제약.

## 실행 방법

### 백엔드

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

### 프런트엔드

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 http://localhost:5173 접속 후 GeoTIFF DEM 파일 업로드.
